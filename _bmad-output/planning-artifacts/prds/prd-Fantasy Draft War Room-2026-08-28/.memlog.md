- (decision) Create a canonical PRD companion from the validated product specification; preserve docs/fantasy-draft-war-room-spec.md as the authoritative technical source to avoid destructive restructuring.
- (assumption) Use the documented Version 1 scope as the MVP baseline; unresolved data-source, policy, and calibration decisions remain explicit open questions rather than inferred product commitments.
- (change) Created canonical PRD draft with V1 scope boundaries, five operator journeys, version allocation for FR/NFRs, measurable acceptance criteria, success and counter-metrics, and explicit open questions derived from validation findings.
- (decision) DEC-01 resolved: the V1 snapshot is prepared locally before the draft by a command-line script.R; the live runtime consumes only the generated snapshot and never accesses the network.
- (decision) DEC-02 resolved: on opening or reload, list local sessions newest first with the newest preselected; the user may confirm it or select another session before restoration.
- (decision) DEC-03 resolved: use an Intel MacBook Pro as the V1 benchmark baseline; it is not a product compatibility gate, and every run records its actual hardware and measurement tool.
- (decision) DEC-04 resolved: V1 supports configurable team count, rounds, starter slots, bench slots, and FLEX eligibility; the documented league is the initial version of configuration files, not a scope boundary.
- (decision) DEC-05 resolved: recommendation weights and policies are configurable in V1 through versioned configuration files prefilled with the initial recommended strategy; active configuration is recorded per session.
- (decision) DEC-06 resolved: correcting an earlier pick automatically recomposes downstream state; if it would create a duplicate or other invalid state, reject it with a clear reason and retain every later pick.
- (decision) DEC-07 resolved: scoring is configurable in V1 through YAML compatible with ffanalytics, with Full PPR supplied as the initial default; the session must use a snapshot produced under the same scoring configuration.
- (decision) DEC-08 resolved: validate V1 through an assisted test with at least five fantasy managers, targeting at least four completing the flow without code changes and explaining the top recommendation; this is an early usability signal only.
- (decision) DEC-09 resolved: V1 snapshots and projections are for the operator local use only; the application neither distributes data nor integrates external sources during the live runtime.
- (decision) DEC-10 resolved: V1 does not ingest live news or injury updates during the draft; a new snapshot may be selected only before the draft starts.
- (decision) DEC-11 resolved: V1 supports 8–14 teams and exactly 15 rounds, with 9 starters (QB, WR, WR, RB, RB, FLEX RB/WR, TE, K, D/ST) and 6 bench slots; only RB/WR are FLEX-eligible.
- (decision) DEC-12 resolved: the V1 assisted usability test is a complete 15-round draft including a correction, reload, and export; acceptance and usability metrics use this same scenario.
- (event) PRD finalized after resolving the configuration envelope, full usability scenario, and versioned data-contract companion.
