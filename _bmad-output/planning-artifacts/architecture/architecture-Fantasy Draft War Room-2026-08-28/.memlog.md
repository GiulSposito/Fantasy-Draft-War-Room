- (decision) AD-1 [ASSUMPTION]: V1 uses Hexagonal Architecture with a functional core and imperative shell; Shiny is a presentation adapter, application use-cases own orchestration, domain is pure, and filesystem/SQLite/YAML are adapters.
- (decision) AD-2 [ADOPTED]: Preparation is a separate local CLI pipeline. It may use ffanalytics and network access; its only live-runtime handoff is a validated immutable snapshot bundle with content hash and QA metadata.
- (decision) AD-3 [ADOPTED]: Live draft commands mutate only through application use-cases and append immutable events in a single SQLite transaction; read state is rebuilt deterministically from the event stream and persisted as a replaceable projection.
- (decision) AD-4 [ADOPTED]: A started session pins snapshot content hash, league/scoring config hash, recommendation policy hash, engine version, and optional seed. Those values cannot change in place.
- (decision) AD-5 [ASSUMPTION]: The V1 runtime is a single-user local Shiny process bound to loopback, with its SQLite database, exports, and logs stored under an OS user-data directory. It has no network dependency or public deployment surface.
- (decision) AD-6 [ADOPTED]: Fast recommendations are deterministic domain calculations over the frozen state, prepared player metrics, and active policy. They return ranked candidates plus structured factors and reason codes; V2 market forecasting and V3 simulation remain outside V1.
- (decision) AD-7 [ASSUMPTION]: Configuration is versioned YAML validated into canonical in-memory objects; its canonical serialized form is hashed before it enters a session. Runtime configuration is read-only after start.
- (decision) AD-8 [ADOPTED]: SQLite schema constraints are the final integrity barrier for event sequence, slot identity, and effective player selection; domain validation must reject invalid commands before persistence and leave later events intact.
- (version) Reality checked 2026-08-28: R 4.6.0, shiny 1.14.0, DBI 1.3.0, RSQLite 3.53.3; ffanalytics remains a GitHub-installed package and must be locked by immutable commit in renv.lock.
- (constraint) PRD decisions DEC-01 through DEC-12 are binding, notably: live runtime has no network access; snapshot selection only before start; 8–14 teams, 15 rounds, 9 starters plus 6 bench; scoring/policies configured from versioned files; correction preserves downstream events if invalid.
